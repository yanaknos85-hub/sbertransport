# Бизнес-требования (БТ) v4.0 — ETRN (ЭТрН)

> Источник: TRANSPORT-44256, 13 SP
> Дата актуализации: 2026-07-20

---

## 1. Ключевая цель

Создать **самостоятельный `etrn-service`** с устойчивой моделью хранения — **Этап 1**.  
Сервис отвечает за жизненный цикл карточки ЭТрН (электронная транспортная накладная) в контуре перевозки Т1–Т4.

---

## 2. Принципы

| # | Принцип |
|---|---------|
| 1 | **Одна карточка** на цепочку Т1–Т4 |
| 2 | **Банк подписывает только Т3** (Титул 3) |
| 3 | Этап считается завершённым **только после `ACCEPTED_BY_KORUS`** |
| 4 | После завершения этапа данные **не удаляются** — меняется проекция (ReadModel) |
| 5 | PDF/XML **не обязательны** для readiness на Этапе 1 |

---

## 3. Статусная модель карточки

### 3.1. Статусы карточки (этап жизненного цикла)

```
IDENTIFIED → WAIT_KORUS_DATA → WAIT_CONDITIONS / READY → WAIT_KORUS_CONFIRMATION → COMPLETED
```

| Статус | Описание |
|--------|----------|
| IDENTIFIED | Карточка создана, идентичность разрешена |
| WAIT_KORUS_DATA | Ожидание входящих данных от КОРУС |
| WAIT_CONDITIONS / READY | Ожидание/готовность условий (валидация пройдена) |
| WAIT_KORUS_CONFIRMATION | Ожидание подтверждения от КОРУС |
| COMPLETED | Этап завершён (ACCEPTED_BY_KORUS) |

### 3.2. Статусы Т3 (Титул 3)

```
EXPECTED / AVAILABLE → WAIT_CONDITIONS → READY_TO_SIGN → SIGNING → SIGNED_LOCALLY → SENT_TO_OPERATOR → ACCEPTED_BY_OPERATOR / REJECTED
```

| Статус | Описание |
|--------|----------|
| EXPECTED / AVAILABLE | Т3 ожидается / доступен |
| WAIT_CONDITIONS | Ожидание выполнения условий |
| READY_TO_SIGN | Готов к подписанию |
| SIGNING | В процессе подписания |
| SIGNED_LOCALLY | Подписан локально (УКЭП) |
| SENT_TO_OPERATOR | Отправлен оператору |
| ACCEPTED_BY_OPERATOR / REJECTED | Принят / отклонён оператором |

### 3.3. Статусы signing operation (операция подписания УКЭП)

```
CREATED → SIGNING → SIGNED_LOCALLY → SENDING_TO_KORUS → ACCEPTED_BY_KORUS / REJECTED_BY_KORUS / OUTCOME_UNKNOWN / ERROR
```

| Статус | Описание |
|--------|----------|
| CREATED | Операция создана |
| SIGNING | Идёт подписание |
| SIGNED_LOCALLY | Подписано локально |
| SENDING_TO_KORUS | Отправляется в КОРУС |
| ACCEPTED_BY_KORUS | Подтверждено КОРУС |
| REJECTED_BY_KORUS | Отклонено КОРУС |
| OUTCOME_UNKNOWN | Исход неизвестен |
| ERROR | Ошибка |

### 3.4. Lease lock (блокировка)

**Краткоживущая блокировка** Т3 при открытии окна подписания:
- Применяется на время сессии подписания
- Предотвращает параллельные операции над тем же Т3

## 4. Бизнес-правила (BR-01 – BR-09)

| Код | Правило |
|-----|---------|
| BR-01 | Одна карточка ЭТрН на одну цепочку |
| BR-02 | Банк подписывает строго Т3 |
| BR-03 | Нельзя подписать Т3 без наличия Т1 и Т2 |
| BR-04 | Идемпотентность: повторный вызов не создаёт дубликат |
| BR-05 | Т3 подписывается после прохождения всех условий готовности |
| BR-06 | Завершённый этап не удаляет данные — меняет проекцию |
| BR-07 | Статусы строго детерминированы, переходы по разрешённой матрице |
| BR-08 | Подписание — атомарная транзакция: aggregate + event + outbox |
| BR-09 | Ошибки валидации возвращаются с кодом и описанием |
