# Риски и production gates

## Production gates

| Gate | Описание | Влияние | Контроль |
| --- | --- | --- | --- |
| **G-01** | **Контракт КОРУС не утверждён.** Методы API, поля, auth-схема, sandbox-доступ и коды результата не подтверждены официально. | Блокирует production enablement интеграции с КОРУС. | Feature flag + mocks + contract tests. |
| **G-02** | **УКЭП/МЧД — юридическая модель не определена.** Не утверждён signing adapter, схема полномочий, выпуск сертификатов и юридическая модель ПЭП/основания приёмки. | Подпись может быть юридически ничтожна. | Не подменять HTTP-событием; отдельный gate на юридическую модель. |
| **G-03** | **Справочник юрлиц Банка — нет надёжного match receiver.** Нет утверждённого master-data источника для определения принадлежности юридического лица к Банку. | Невозможно надёжно определить роль Банка (bank_is_receiver). | Configuration/reference adapter; PENDING при недостатке данных. |
| **G-04** | **Нагрузка/TTL lock не протестированы.** Lock TTL, polling, retry, конкурентный доступ не проверены под нагрузкой. | Риск зависаний и блокировок в production. | Load/resilience tests до включения feature. |

## Бизнес-риски

| ID | Риск | Описание | Влияние | Митигация |
| --- | --- | --- | --- | --- |
| **R-00-01** | **Реализация только под Т3 — переделка модели.** Если модель будет захардкожена только под Т3, последующие этапы (Т1, Т1+Т3) потребуют переделки схемы. | Высокие затраты на перестройку модели. | Инвариант I-09: общие сущности не хардкодят Т3 как единственный банковский титул. |
| **R-00-02** | **Инициатор = подписант (ошибка).** Инициатор процесса (bank_is_initiator) ошибочно признаётся отправителем/получателем для целей подписания. | Появление в очереди Банка титула без юридической обязанности. | Раздельное хранение bank_is_sender, bank_is_receiver, bank_is_initiator (BR-00-BE03-001/002). |
| **R-00-03** | **Неполное хранение идентификаторов.** Потеря исходных (original) идентификаторов ЭТрН при нормализации. | Невозможность аудита и корреляции с КОРУС/ЦС. | Хранить original + canonical идентификатор без потери исходного представления (BR-01-API03-008). |
| **R-00-04** | **route = маршрут АС СБТ.** `routeContext` ошибочно воспринимается как маршрут планировщика АС СберТранспорт. | Создание ложных маршрутов, обращения в поддержку. | I-07, BR-07: route — только внешний контекст; внутренний маршрут не создаётся. |
| **R-00-05** | **Нет частичного результата по etrn[].** Массив обрабатывается как одна атомарная единица. | Ошибка одного элемента блокирует все остальные. | BR-09: ошибка одного etrn item не откатывает durable регистрацию остальных. |
| **R-00-06** | **PDF не учтён.** PDF-форма не предусмотрена в readiness-проверке или хранении. | Невозможность сверки при подписании. | PDF/XML не blocking requirement Этап 1 (BR-09), но статус PDF ведётся отдельно. |
| **R-00-07** | **Документ завис в работе.** Т3 взят в работу, но не подписан и не возвращён. | Документ недоступен другим подписантам. | Регламент возврата в очередь; права поддержки/администратора на снятие блокировки. |
| **R-00-08** | **Недостаточная детализация ошибок.** Ошибки возвращаются без различимых кодов reasonCode / externalErrorCode. | Невозможность диагностики и поддержки. | Единый event/error catalog ETRN-06-BE-01; reasonCode и externalErrorCode хранятся отдельно от канонического кода. |

## Технические риски

| ID | Риск | Описание | Влияние | Митигация |
| --- | --- | --- | --- | --- |
| **R-01** | **Не определён лимит etrn[]** | Большие payload, таймауты, неопределённое SLA. | Согласовать maxItems, размер запроса, таймауты. |
| **R-02** | **Нет eventId/correlationId в API** | Сложнее обеспечить идемпотентность и трассировку. | Использовать route + etrn[i] + dateTimeCreate + payload hash. |
| **R-03** | **200 OK без тела не показывает частичный результат** | ЦС не понимает, какие ЭТрН приняты, дублированы или отклонены. | Согласовать response model с per-item статусами. |
| **R-04** | **Не определён способ получения PDF** | Нельзя обеспечить сверку и UX подписи. | Уточнить API: файл, ссылка, contentId, срок жизни. |
| **R-05** | **PDF содержит ПДн** | Риски ИБ/КБ. | Согласовать хранение, аудит, права доступа. |
| **R-06** | **Не решено, блокирует ли отсутствие PDF подпись** | Либо задержка, либо риск подписи без сверки. | Принять PO/Legal решение. |
| **R-07** | **Не согласован срок хранения raw payload** | ИБ/Legal риски. | Утвердить retention policy до PROD. |
| **R-08** | **Операторские коды напрямую сохраняются как внутренние** | Зависимость домена от КОРУС. | Маппинг в ETRN-00-BE-04; raw external status хранить отдельно. |
| **R-09** | **Не согласовано, должен ли PDF блокировать подпись** | Разные правила готовности. | Отдельный статус и параметризуемое условие. |
| **R-10** | **Не утверждены production-длительности SLA** | Невозможно определить нормативную просрочку. | PO утверждает конфигурацию; engine не использует скрытые значения. |
| **R-11** | **Нет согласованного master-data источника организаций Банка** | Невозможно надёжно определить роль. | Назначить владельца НСИ до DoR. |
| **R-12** | **Транзакционная модель по items может усложнить recovery** | Частичный сбой трудно восстанавливать. | Зафиксировать unit-of-work: package + item поэлементно или общий commit с savepoint. |
