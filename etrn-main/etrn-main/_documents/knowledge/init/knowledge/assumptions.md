# Документированные предположения (Assumptions)

## Инварианты

| ID | Предположение | Контекст |
| --- | --- | --- |
| **A-01** | **Одна карточка = одна ЭТрН (неоспоримый инвариант).** Одна карточка ЭТрН хранит всю цепочку Т1–Т4. Т1–Т4 не создают отдельные карточки. | BR-01, I-01, ETRN-00-BE-01 |
| **A-02** | **PDF/XML не влияют на readiness Этап 1.** PDF и XML не являются обязательным условием readiness для подписания Т3 на Этапе 1. | BR-09, ETRN-00-BE-01 v4.0 |
| **A-03** | **routeContext — только внешний контекст, не маршрут АС СБТ.** `routeContext` хранится как внешний контекст доставки ЦС и не создаёт внутренний маршрут в АС СберТранспорт. | I-07, ETRN-01-BE-API-01 |
| **A-04** | **HTTP 200 = только приём в работу, не успех подписания.** HTTP 200 на /cs/title3 означает durable регистрацию события, а не завершение подписания Т3 или принятие КОРУС. | BR-08, G-01-03 |
| **A-05** | **Lock — краткоживущий lease (5 мин по умолчанию, конфигурируемо).** Блокировка при открытии окна подписания — lease на 5 минут. Настраивается через конфигурацию. | ETRN-00-BE-01 |
| **A-06** | **Optimistic locking в EtrnRepository.** Агрегат использует оптимистичную версионную блокировку (optimistic lock), а не пессимистичную. | ETRN-00-BE-01 |
| **A-07** | **OUTCOME_UNKNOWN запрещает повторную подпись до reconciliation.** При неопределённом результате подписания (OUTCOME_UNKNOWN) новая операция подписи невозможна до выполнения reconciliation. | BR-08, I-05 |
| **A-08** | **Batch etrn[] не обрабатывается в одной long transaction.** Массив идентификаторов ЭТрН обрабатывается по каждому элементу независимо, без единой долгой транзакции для всего пакета. | ETRN-00-BE-01 (производительность) |
| **A-09** | **КОРУС использует адресную синхронизацию (не polling всех документов).** Запрос к КОРУС выполняется адресно по известному идентификатору ЭТрН. Общий polling всех документов Банка не выполняется. | BR-07, ETRN-00-BE-04 |
| **A-10** | **Feature flags для функциональности.** Функциональность разделяется feature flags: inbound CS, KORUS fetch, signing UI, submit/reconcile, completion. | ETRN-00-BE-01 |
| **A-11** | **Инициатор ≠ подписант.** `bank_is_sender`, `bank_is_receiver` и `bank_is_initiator` — разные признаки и хранятся раздельно. Инициирование процесса не означает юридическую роль отправителя или получателя. | BR-00-BE03-001/002 |
| **A-12** | **Без хардкода «единственный банковский титул = T3» (I-09).** Общие сущности не хардкодят Т3 как единственный возможный титул Банка. Доступность Т1/Т3 определяется ролью Банка, этапом и feature flag. | I-09, ETRN-00-BE-01 |
| **A-13** | **После PROCESS_COMPLETED физическое удаление запрещено.** После завершения карточка меняет проекцию (исчезает из активного списка), но данные и история физически не удаляются. | BR-06, I-06 |
| **A-14** | **Секреты КОРУС/УКЭП хранятся вне бизнес-таблиц.** Учётные данные, ключи и сертификаты для взаимодействия с КОРУС и УКЭП не сохраняются в бизнес-таблицах и не попадают в логи. | ETRN-00-BE-01 |

## Поведенческие

| ID | Предположение | Контекст |
| --- | --- | --- |
| **A-15** | **T3 не может быть READY_FOR_UKEP без подтверждённых Т1 и Т2.** Т3 готов к подписанию только при наличии подтверждённых Т1, Т2, актуальных данных Т3 и успешной validation. | BR-03, ETRN-00-BE-01 |
| **A-16** | **Не более одной active signing operation и lock для Т3.** В один момент времени существует не более одной активной операции подписи и одного активного lock для Т3. | BR-07, ETRN-00-BE-01 |
| **A-17** | **Этап завершён только после ACCEPTED_BY_KORUS.** Завершение Этапа 1 наступает только после подтверждения КОРУС; локальной подписи недостаточно. | BR-05, ETRN-00-BE-01 |
| **A-18** | **Ошибка одного etrn item не откатывает остальные.** Частичный сбой/ошибка одного элемента массива etrn[] не блокирует обработку остальных валидных элементов. | BR-09, ETRN-01-BE-API-01 |
| **A-19** | **Readiness — результат проверки, а не состояние.** Readiness — это результат проверки условий, а не хранимое состояние карточки. | Определение термина |
| **A-20** | **Внешний Т1/Т3 не попадает в очередь Банка.** Внешний Т1, Т2, Т4 не получают признак банковского действия (bankActionRequired) и не попадают в очередь подписания Банка. | ETRN-00-BE-02/03 |

## Архитектурные

| **A-22** | **RBAC и минимальное раскрытие реквизитов.** ФИО, водитель, актор и реквизиты показываются в минимально необходимом объёме. | ETRN-00-BE-01 |
| **A-23** | **Внутренние API/DTO для FE, /cs/title3 и KORUS facade.** Внутренние контракты DTO отделены от внешних. | ETRN-00-BE-01 |
| **A-24** | **SLA имеет версионность и конфигурацию.** Длительность SLA не зашивается в код, а конфигурируется. | ETRN-06-BE-02 |
