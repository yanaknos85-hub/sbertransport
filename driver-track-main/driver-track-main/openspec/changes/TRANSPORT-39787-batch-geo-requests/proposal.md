## Why

Geo-сервис имеет ограничение на количество точек в запросе — не более 500 координат.

Водитель может накопить больше 500 GPS-точек за поездку (потеря связи, длительная поездка). Текущая реализация `GeoClientImpl.recreateRoute()` отправляет все координаты одним запросом, что приведёт к ошибке geo-сервиса при превышении лимита.

Необходимо разбивать запрос на батчи по 500 точек и агрегировать результаты в единый маршрут.

## What Changes

- Изменение `GeoClientImpl.recreateRoute()`: разбивка координат на батчи по N точек (конфигурируемо)
- Отправка каждого батча в geo-сервис отдельным gRPC-запросом
- Агрегация результатов: суммирование `distance`, объединение `segments` из всех батчей
- Конфигурация размера батча через `@Value("${geo.batch-size:500}")`
- Логирование: количество координат и число батчей

### Non-goals

- Не меняем расчёт `time` (всегда null, как сейчас)
- Не меняем интерфейсы `GeoClient` — сигнатура остаётся прежней
- Не меняем `CalculateRouteService` — он не знает о батчинге
- Не добавляем частичную обработку ошибок (если батч упал — весь метод падает)

## Impact

| Модуль | Изменение |
|--------|-----------|
| `service.impl.GeoClientImpl` | Основная логика: батчинг, агрегация, логирование |
| `application.yml` | Конфиг `geo.batch-size` |
| `service.impl.GeoClientImplTest` | Тесты для сценариев с >500 точек |

Зависимости: нет новых.
Риски: минимальные — gRPC-клиент, увеличенное число запросов к geo.
