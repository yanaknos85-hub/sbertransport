    # Спецификация: Метод предоставления списка уникальных ИНН контрагентов для штрафов

## 1. Назначение

Доработка существующего gRPC-сервиса диспетчеризации добавлением нового метода для предоставления списка **уникальных ИНН контрагентов**,满足 которым требуется выполнять запрос штрафов.

## 2. Термины и определения

| Термин | Определение |
|--------|-------------|
| **Организация** | Юридическое лицо или подразделение, которому принадлежат транспортные средства |
| **B2G** | External system для получения информации о штрафах из государственных источников |

## 3. Функциональные требования

### 3.1. Получение списка уникальных ИНН контрагентов

**ID требования:** FR-001

**Описание:**

Существующий gRPC-сервис должен предоставлять новый метод для получения списка уникальных ИНН контрагентов.

Фильтр определяется в FR-002.

**Входные данные:**

| Параметр | Тип | Обязательный | Описание |
|-----------|------|--------------|----------|
| Нет | — | Нет | Запрос пустой, фильтр применяется по умолчанию (FR-002) |

**Выходные данные:**

Список уникальных ИНН контрагентов (поле `tins` в gRPC response):

| Поле в gRPC DTO | Тип Proto3 | Описание |
|-----------------|------------|----------|
| `tins` | `repeated string` | Список уникальных ИНН организаций (10 или 12 цифр) |

### 3.2. Фильтрация

**ID требования:** FR-002

**Описание:**

В ответ включаются только организации, по **всем** следующим условиям:

| Условие | Описание |
|---------|----------|
| `active = true` | Организация считается активной в системе |
| `is_fine_fetch_required = true` | Для организации включена настройка запроса штрафов |

**Примеры:**

| Организация | active | is_fine_fetch_required | Включена в ответ? |
|-------------|--------|------------------------|--------------------|
| ООО «Автопарк 1» | true | true | ✅ Да |
| ООО «Автопарк 2» | true | false | ❌ Нет |
| ООО «Автопарк 3» | false | true | ❌ Нет |
| ООО «Автопарк 4» | false | false | ❌ Нет |

### 3.3. Уникальность ИНН

**ID требования:** FR-003

**Описание:**

В ответе возвращаются только **уникальные ИНН контрагентов**. Если в БД присутствует несколько записей одной и той же организации с одинаковым ИНН, в ответе возвращается только одна запись.

**Пример:**

| Организация | tin | Включена в ответ? |
|-------------|-----|--------------------|
| ООО «Автопарк А» | 7707083893 | ✅ Да (первая встреченная) |
| ООО «Автопарк А» (филиал) | 7707083893 | ❌ Нет (дубликат ИНН) |
| ООО «Автопарк Б» | 7701234567 | ✅ Да |

## 4. API Contract

### 4.1. Существующий сервис `DispatcherService`

| Метод                          | Описание |
|--------------------------------|----------|
| *(существующие методы)*        | *(определены предыдущими спецификациями)* |
| `getOrganizationsForPenalties` | **Новый метод** — получение списка уникальных ИНН контрагентов для запроса штрафов |

### 4.2. Метод `getOrganizationsForPenalties`

**gRPC Service:** `DispatcherPenaltyService`

**Прото-определение:**

```proto
service DispatcherPenaltyService {
  rpc GetOrganizationsForPenalties (GetOrganizationsForPenaltiesRequest)
      returns (GetOrganizationsForPenaltiesResponse);
}

message GetOrganizationsForPenaltiesRequest {
}

message GetOrganizationsForPenaltiesResponse {
  repeated string tins = 1;
}
```

**Запрос:**

| Параметр | Тип | Обязательный | Описание |
|-----------|------|--------------|----------|
| Нет | — | Нет | Запрос пустой (`GetOrganizationsForPenaltiesRequest`) |

**Ответ:**

| Поле | Тип Proto3 | Описание |
|------|------------|----------|
| `tins` | `repeated string` | Список уникальных ИНН контрагентов |

**Реализация:**

- **Controller (gRPC):** `DispatcherPenaltyGrpcServiceImpl`
- **Repository метод:** `ContractorRepository.findDistinctTinByActiveIsTrueAndIsFineFetchRequiredIsTrue()`
- **SQL:** `SELECT DISTINCT c.tin FROM Contractor c WHERE c.active = true AND c.is_fine_fetch_required = true`

### 4.4. Примеры сообщений

**Запрос (gRPC):**
