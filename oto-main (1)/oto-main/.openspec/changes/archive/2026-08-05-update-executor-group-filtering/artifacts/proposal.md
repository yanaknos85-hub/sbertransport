1# Proposal: Обновить логику фильтрации заявок по группам исполнителей

## Что

Необходимо доработать логику фильтрации заявок в разделе «Исполнение заявок» при выборе режима группировки «По группам исполнителей».

## Зачем

Текущая логика фильтрации по группам исполнителей не поддерживает сценарий выбора «Без групп» и некорректно обрабатывает пустой список выбранных групп. Требуется явная поддержка трёх режимов фильтрации.

## Проблема

В текущей реализации отсутствуют следующие сценарии:
- Фильтрация по пустому списку групп («Все группы») — должна отображаться вся лента заявок без фильтрации
- Фильтрация по заявкам без группы исполнителя («Без групп») — необходимо отображать только заявки, у которых отсутствует группа исполнителей

## Решение

Внедрить поддержку трёх режимов фильтрации на основе параметров `emptyExecutorGroup` и `executorGroupIds`:

| Режим | emptyExecutorGroup | executorGroupIds | Поведение |
|-------|-------------------|------------------|-----------|
| Все группы | `false` | `[]` | Фильтрация отсутствует, отображаются все заявки |
| Без групп | `true` | `[]` | Отображаются только заявки без группы исполнителя |
| Конкретные группы | `false` | `[id1, id2]` | Отображаются заявки, соответствующие выбранным группам |

## Изменения

- Модификация запроса к API: обработка параметров `emptyExecutorGroup` и `executorGroupIds`
- Изменение бизнес-логики фильтрации в сервисном слое
- Изменение репозиторийного слоя (Criteria/Query построение)
