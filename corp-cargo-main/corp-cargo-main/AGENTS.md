# AGENTS.md — Краткие правила для AI-агентов в проекте Cargo

> Файл с коротким, но обязательным к прочтению контекстом для любого AI-ассистента (GigaCode, Copilot, Cursor и т.п.).
> Подробный контекст проекта — в [`GIGACODE.md`](./GIGACODE.md). Этот файл — «первая страница», без чтения которой нельзя трогать код.

## 🚫 Версии библиотек — НЕ менять без согласования

Версии **жёстко зафиксированы** в `package.json` (через `dependencies` + `resolutions`). Обновление мажорных версий ломает совместимость со всем проектом и хост-приложением.

| Библиотека | Текущая версия | Запрещено |
|---|---|---|
| **React** | `16.14.0` | ❌ React 17, 18, 19 (нет Concurrent features, типы рассчитаны на v16) |
| **React Router DOM** | `5.3.0` | ❌ Router 6, 7 (API другой: `useHistory`/`Switch` → `useNavigate`/`Routes`) |
| **MobX** | `^5.15.4` | ❌ MobX 6+ (`makeAutoObservable` отсутствует в v5, нужен `makeObservable`) |
| **Ant Design** | `4.17.2` | ❌ antd 5+ (другая тема, отсутствуют некоторые компоненты) |
| **React Query** | `2.26.4` | ❌ react-query 3+ (API `useAPI` helper использует v2-сигнатуру) |
| **TypeScript** | `5.2.2` | ⚠️ Не ниже 5.0 (декораторы + `emitDecoratorMetadata`) |
| **io-ts** | `^2.2.4` | ❌ io-ts 3+ (синтаксис другой) |

**Правило:** если предлагаемое решение требует новой версии — значит, решение неверное. Ищи другой способ.

## 📖 Где брать контекст проекта

> ⚠️ **AI-агент, прочитай это ПЕРЕД началом работы.**
> Хосты не подхватывают файлы из `docs/` автоматически — только этот `AGENTS.md` и `GIGACODE.md` попадают в системный промпт. Остальное открывай через `read_file` по карте ниже.

Перед началом работы **обязательно** прочитать:

0. **[`docs/INDEX.md`](./docs/INDEX.md)** — индекс всей документации с картой «когда какой файл читать». **Начни с него.**
1. **[`GIGACODE.md`](./GIGACODE.md)** — полный контекст: стек, конвенции, decision log, словарь предметной области, известные расхождения.
2. **Релевантный `docs/*.md`** — по карте из `docs/INDEX.md` (например, для API → `docs/API_LAYER.md`, для сторов → `docs/STATE_MANAGEMENT.md`).
3. **`src/modules/<Module>/<Module>.architecture.md`** — если работа идёт в конкретном модуле (например, `Planner.architecture.md`).
4. **`eslint.config.js`** — чтобы не предлагать тесты/линт для модулей из `ignores` (Planner, Contractors, TariffSettings и др. — **не линтуются**).
5. **`jest.config.ts`** — `collectCoverageFrom` указывает, что **не покрывается** тестами (`api/**`, `ioc/**`, `constants/**`, `types/**`, `*.d.ts`, `*.test.*` и т.д.).

**Если файл `GIGACODE.md` отсутствует или устарел** — сообщить пользователю и не приступать к задаче.

## 🛠️ Доступные скиллы

Скиллы вызываются через `skill: "<name>"` или `/<name>`. Расположены в `~/.gigacode/skills/`.

| Скилл | Когда вызывать |
|---|---|
| **`commit`** | После завершения фичи/фикса и подтверждения пользователем. Создаёт commit message по conventional commits (только `feat`/`fix` с префиксом `TRANSPORT-`), body ≤ 100 символов/строка, добавляет `Co-authored-by: GigaCode Assistant <gigacode@sberbank.ru>`. **Не вызывать**, если изменения не проверены и не одобрены. |
| **`merge-branch`** | Когда нужна новая ветка для задачи (по ключевым словам: номер задачи `TRANSPORT-NNNNN`, тип — фича/баг). **Не вызывать**, если пользователь явно не попросил создать ветку. |
| **`test`** | Когда нужно: написать тесты, увеличить покрытие, проанализировать что покрыто. Скилл сам проверит `jest.config.ts` (исключения) и `sonar-project.properties`. **Не вызывать** для простых smoke-тестов или для кода из `collectCoverageFrom`-исключений. |

### Правила вызова скиллов

- **Скилл — это переиспользуемый промпт.** Если задача не подходит под описание скилла — не вызывать его насильно, лучше выполнить задачу вручную.
- **Перед вызовом скилла `commit`** убедиться: `yarn lint` пройден (если модуль линтуется), `yarn test` зелёный, conventional-commit формат соблюдён.
- **Перед вызовом скилла `merge-branch`** уточнить у пользователя тип ветки (`feat/` или `fix/`) и номер задачи, если не указаны явно.

## ⚡ Быстрые ссылки на конфиги

| Конфиг | Путь | Что проверять |
|---|---|---|
| Версии зависимостей | [`package.json`](./package.json) | `resolutions`, `dependencies` — не апгрейдить мажоры |
| ESLint ignores | [`eslint.config.js`](./eslint.config.js) | Список модулей, для которых линт отключён |
| Jest покрытие | [`jest.config.ts`](./jest.config.ts) | `collectCoverageFrom` — что исключено из coverage |
| Commit format | [`commitlint.config.js`](./commitlint.config.js) | Разрешённые типы: `feat`/`fix`, префикс `TRANSPORT-` |
| TS-конфиг | [`tsconfig.json`](./tsconfig.json) | `strict: true`, `experimentalDecorators`, `baseUrl: ./src` |
| Git hooks | [`lefthook.yml`](./lefthook.yml) | pre-commit: lint, pre-push: node + package check |

## 🚨 Если сомневаешься

0. **Открой [`docs/INDEX.md`](./docs/INDEX.md)** — там карта «когда что читать» и оглавление всех файлов.
1. **Прочитай `GIGACODE.md`** — большинство вопросов уже задокументированы (decision log, словарь, предупреждения).
2. **Спроси пользователя**, прежде чем:
   - менять версии зависимостей,
   - рефакторить смежный код «по пути»,
   - трогать модули из ESLint ignores (Planner, Contractors, TariffSettings…),
   - менять conventional-commit формат,
   - добавлять новые зависимости в `package.json`.
3. **Запусти проверки** перед сдачей: `yarn lint` (если модуль линтуется), `yarn test`, `yarn build` (если менялся webpack/конфиги).
